# 00 · 复盘与窗口协议(2026-06-11,树成林手册站全程复盘)
> 本目录 = 「网站工厂」:把这次 12 小时的经验固化成产线。新项目第一步=读完本目录四个文件再开工。

## 一、这次的工作流到底是什么(实况)

```
人(审核员/出题人)
   │  素材+参考视频+审美判决
   ▼
总规划窗口(本窗) ──┬─ 拆解参考(11视频→并行分析队→REF-BIBLE)
                  ├─ 定契约(颜色/字体/缓动/章节/文案铁律)
                  ├─ 写发令单(每窗一段,自包含,贴回即开工)
                  ├─ 总装(插桩/重编号/跨章胶水/冲突仲裁)
                  ├─ 机器质检(无头探针:逐章截图+0错+404+fps)
                  └─ 部署+保密(打包/混淆/上线/冒烟)
   │ 发令单(人手动贴 → 后期可 send_message)
   ▼
执行窗 A(基建+序章) B(作品章) C(技能章) D(素材河+终幕) E(视频矩阵)
   各自:读契约 → 施工自己前缀的文件 → 自跑 QA 脚本 → 把交付状态写进项目记忆
```

## 二、控质与监测的三件套(已验证有效)
1. **合并契约(CONTRACT.md)**:类名前缀分仓、FX API 唯一、颜色白名单、已踩坑清单——窗口间零冲突的根因。
2. **即交即验**:每窗交付必附自跑 QA 脚本与截图;总装再跑全站探针(qa-tools/probe-*.js:逐章定位截图+console 0 错+404=0+fps)。机器管"坏没坏"。
3. **项目记忆(memory/showcase-site-project.md)**:所有窗口共写的"黑匣子"——交付状态、参数、坑。窗口死了,记忆还在,新窗口读完即接力。

## 三、窗口互通的真实答案(按自动化程度排)
| 级别 | 机制 | 现状 |
|---|---|---|
| L1 文件信箱 | 项目记忆+CONTRACT+发令单(人贴) | ✅本次主力,稳但要人搬运 |
| L2 定向消息 | 总控 list_sessions/send_message 直发各窗(每条点一次"允许") | ✅已验证可用,**要求权限非"自动放行"模式** |
| L3 一键开窗 | 总控 spawn 任务卡片,人点一下即开新窗带任务开工 | ✅已用(E窗即此) |
| L4 真子代理 | 总控用 Agent/Workflow 在自己进程里并行开工(11视频拆解=11子代理,零人工搬运) | ✅已用于分析;**下次施工也走这条** |
| 顶级形态 | 编排器+共享任务板+评审代理闭环(造→评→改全自动,人只看终审) | 本目录 01/03 即其落地图纸 |

**结论:复制粘贴可以消失。** 下次开工:分析/质检全走 L4 子代理;长任务施工窗用 L3 一键开 + L2 发令;你只在两处出现——立项时给素材与定位,终审时拍板。

## 四、12 小时弯路审计(钱花在哪、下次省在哪)
| 弯路 | 损耗 | 产线对策(已写入01/03) |
|---|---|---|
| 先动手后契约,初版10秒翻完 | ~2h返工 | 契约先行,任务卡带「沉浸规格+验收断言」 |
| 中段平庸(框接框堆砌)等40-50分钟才被你发现 | ~3h | **交付前强制过"质检官"审美五问**(见03),不过关不许交人 |
| 文案被骂三轮(元叙述/一句话/自夸) | ~1.5h | 文案铁律入契约;新文案先过铁律自检 |
| 我自己踩契约已记的坑(CSS transform 初始位移) | ~0.5h | 开工前必读坑库,QA断言含坑回归项 |
| 素材反复找/重复爬 | ~1h | 素材普查脚本第一步跑(01手册§1) |
| 灰度→彩色等大方向反转 | ~1h | 立项问卷10问先锁大方向(01手册§0) |
**结论:同等质量,产线成熟后预估 3-4 小时(-70%)。**

## 五、迭代路线
